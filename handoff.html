Fanfic Reader — Handoff & Migration Notes

Front-end redesign of the Character.ai fanfic reader · June 2026

branch: 0612-handoff compare against: main

This branch is a visual redesign of the reader front-end. Everything here is presentation — the underlying content model and filtering logic are unchanged. To see exactly what moved, compare this branch against main (that is the version you already know).

What changed

1 · Home page (Discover)

The landing page was rebuilt as a browsable, editorial home that sits on top of the existing filter engine — nothing about how works are filtered or loaded changed underneath it.

  • A rotating hero banner at the top.
  • Horizontal “shelves” (Trending, Featured) and a Creators row, each swipeable with arrow buttons.
  • A “Continue Reading” row driven by the reader’s saved progress.
  • Two card styles: an image/cover card and a text-only list card; the page swaps between them.

2 · Visual / Text mode toggle

A floating toggle in the bottom-right switches the whole site between an image-led “visual” mode and a text-led mode. Switching plays a brief full-screen colour sweep (a small WebGL animation) as the transition, replacing the old grey loading placeholders.

3 · Reading page

  • The work header was reordered to a clear hierarchy: cover → tags/badges → title → author (with photo) → description → stats.
  • Each chapter shows a small author line (work title · author) so a reader who lands deep in a story still sees who wrote it.
  • The “story info” pop-up now mirrors that same header layout.
  • Spacing and font sizes were aligned between the header, the cards, and the pop-up.

4 · Search, filters & navigation polish

  • Refined the search dropdown and the sort menu (padding, rounded corners, consistent widths).
  • Centered the top navigation; renamed the first nav item to “Stories.”

5 · Cleanup

Removed unused components and the old loading-placeholder code path that the new transition made obsolete. No behaviour was lost — verified with a full production build.

How to migrate

This is a static Next.js 15 front-end. There is no database or API in this repo — every story is a Markdown file in content/works, and reader state (progress, preferences, mode) is kept in the browser’s local storage. So an authentic migration is mostly about connecting these surfaces to real data.

  1. Diff this branch against main to get the exact, file-level list of changes — that is the source of truth, this page is the summary.
  2. Wire the placeholder data to real sources. Comments, the user’s library/bookmarks, and recommendations are currently sample data. The shapes and exact spots are documented in .claude/docs/wiring-guide.md and .claude/docs/api-contracts.md (look for @DUMMY / @TODO-DEV markers in code).
  3. Add real auth + persistence. Reading progress and saved works are local-storage only today; they’ll need to move to real per-user storage.
  4. Replace the placeholder images under public/ (covers, hero banners, fandom art, the author photo placeholder) with real assets.
  5. Decide on the transition animation. The mode-switch sweep uses a third-party package, glimm — see the note below before keeping it.
Note on the glimm dependency. The colour-sweep transition relies on a small, newly-published, single-maintainer package that is published under a proprietary (all-rights-reserved) licence. Confirm the licence is acceptable for your distribution before shipping. It is only used in two places (src/app/layout.tsx and the mode toggle), so it’s straightforward to swap for a CSS transition or remove if needed.

Run it

Node 22 LTS. npm install then npm run dev (or npm run build for a production build). The production build currently passes with all pages generated.
